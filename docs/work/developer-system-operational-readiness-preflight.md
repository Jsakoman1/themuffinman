## Dirty-worktree rule

All 456 existing changed paths belong to the current workspace state. Every task must
start through the serial verifier before editing and may change only its declared
required paths. The workspace snapshot reports existing state but authorizes no commit,
deletion, restoration, or normalization.

## External-evidence rule

The CI workflow is source configuration only until a remote runner result is observed.
The skill decision may recommend a later skill-creator task but cannot install outside
the workspace. IntelliJ indexing and external release operations remain independent
environment boundaries.

## Runtime rule

Both runtime migrations require an owned local stack and fresh evidence after their
individual task start snapshots. Existing JSON or screenshots do not satisfy the new
tasks. A blocked local database, frontend port, or browser launch is a runtime blocker,
not evidence of failure in static source validation.

## Readiness decision

The planning package may be prepared for goal pursuit only after the first hardening
item is verifier-verified. No implementation item may start before that gate, and the
inventory must advance exactly one task at a time.

## Hardening checks

- YAML parsing covers every `developer-system-operational-readiness-*.yaml` file.
- Atomic hardening and strict serial-inventory audits must both report nine items.
- Work-plan recursion and work-artifact schema audits must remain green.
- `.github/workflows/` routing is assigned to the CI item before the workflow can be
  considered discoverable through normal change validation.
- The retention task produces candidates only; no delete command is part of any leaf
  validation.
- Runtime items own exact post-start JSON and screenshot paths and require an owned
  local stack.
- Skill installation and remote CI execution remain outside the verifier boundary.

When these checks and the hardening task pass, the master may set
`prepared_for_goal_pursuit: true`; the master itself remains draft until implementation
begins through the next serial `work-start` action.
