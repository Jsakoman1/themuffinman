# Dora v0.9 preflight

## Baseline and reuse

`1738e94` is the clean published MuffinMan baseline after Dora v0.8.0 was released and pinned. The v0.8 master remains reused evidence for independent bootstrap, structured knowledge, built-in source analysis, voice safety boundaries, and immutable release/pin sequencing.

Those v0.8 outcomes are baseline-only. v0.9 must not re-count them as new completion. It must produce new independent fixtures for context selection, next-step guidance, changed-path impact, status, findings, decision traceability, cache correctness, exports, and voice evaluation.

## Scope reconciliation

- Agent feedback-loop tasks are one command or one contract at a time; they do not edit a product adapter or infer business rules.
- Project-experience tasks add only neutral setup, status, and discovery mechanics.
- Evidence-intelligence tasks standardize diagnostic data without collapsing static, test, and runtime evidence.
- Performance and extension tasks are explicitly after the finding contract, and cannot claim cache or export output as evidence.
- Release and consumer pin are separate and approval-gated items 17 and 18.

## Risks and controls

1. Context can grow into uncontrolled repository dumping. The context contract must require declared sources, byte bounds, citations, and omitted-source diagnostics.
2. `agent-next` can become speculative planning. It must return only the first serially eligible declared item or a deterministic blocker.
3. Finding migration can break existing report consumers. The finding-envelope task requires a compatibility fixture before any export work starts.
4. Caching can hide changed input. The cache task must compare uncached output and invalidate on parser, manifest, source, and schema change.
5. Voice work can drift into runtime execution. The v0.9 contract allows evaluation fixtures and interfaces only; no provider credential, intent resolver, or mutation adapter.

## Start condition

The plan is ready for goal pursuing because the inventory is globally serial, all 18 mappings are exact, each task has one outcome, bounded required paths, a leaf validation, evidence boundary, and direct predecessor dependency. The first action is documentation-only hardening.
