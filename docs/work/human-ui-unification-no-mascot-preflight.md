# Human UI unification preflight

The verified Business/Home hierarchy, branded shell, local tabs, and existing backend-prepared actions are baseline-only. This program repairs the remaining visual system, Home composition, route adoption, and code fragmentation.

The work is frontend-only and strictly serial. Shared tokens and purpose icons precede the canonical page header; Home follows the canonical header; archetype primitives precede route adoption; style cleanup follows route adoption; desktop and mobile visual evidence close the program.

The first started task is the verifier-controlled atomic hardening review. It confirms the full plan graph and execution boundaries without promoting any later implementation task.

No implementation task may start before the atomic hardening task is verifier-verified. Existing screenshots are comparison context only and cannot close the new runtime tasks.

The prepared inventory contains eleven one-to-one task mappings. Shared and Business style consolidation uses a bounded audit first; only the following personal and marketplace cleanup task invokes the whole-app style guard. This prevents a valid serial task from failing on files intentionally assigned to its successor.

Closeout must resolve representative detail and Business setup destinations from canonical visible links or authenticated seeded responses. Entity and business identifiers must not be hardcoded, and a missing destination fails the audit instead of allowing weaker substitute evidence.

Atomic hardening, plan coverage, recursion, and control-source audits must pass again after every plan edit and immediately before goal pursuing. A scoped System Map impact review confirms the app-shell frontend ownership boundary and requires fresh runtime proof but no backend or capability-registry change.
