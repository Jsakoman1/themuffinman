# Dora v1.7 Codex acceleration goal readiness

## Ready after hardening verification

- Dora v1.6.0 is the released baseline and its verified behavior is not counted again.
- v1.7 has a bounded objective: make confirmed information easier for Codex to obtain,
  order, apply safely, and prove; it does not expand into autonomous product creation.
- The program has seven child plans and one strict sixteen-item execution inventory.
- Every planned task has one observable outcome, exact required paths, a direct
  serial dependency, a non-recursive leaf validation command, and an evidence boundary.
- The first task is atomic hardening and has no external side effects.

## Deferred approval gates

No external approval is required to start the hardening task or the planned local
Ruby-contract work. Any future package download, compile dependency resolution,
database/Docker startup, browser runtime scenario, real-data operation, credential
operation, deployment, publication, or release remains a separately approved action.

## Goal completion evidence

The goal can complete only when every inventory item is verifier-marked verified,
all child plans and the master verify, a fresh consumer proves the local v1.7 route,
and the public guide states all product and external-operation boundaries. That still
does not prove a consumer application's business acceptance, security, accessibility,
runtime behavior, production readiness, or release.
